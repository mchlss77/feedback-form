# Code review / аудит

Дата: 09.11.2026. Обсяг: `index.html`, `assets/css/styles.css`, `assets/js/validation.js` (до розділення на два файли), документація.

Як перевіряли:

- **JS-помилки й логіка**: юніт-тести валідаторів у Node (74 кейси) і наскрізний прогін у headless Chrome (50 перевірок) зі збором `console.error` і винятків.
- **Доступність**: статичний аналіз DOM (label, name, `aria-*`, унікальні id), порядок Tab, пастка фокусу, Esc, обчислення контрасту за формулою WCAG у браузері.
- **Адаптивність**: 320 / 768 / 1280px, пошук елементів за межами в'юпорту, висота цілей дотику, скриншоти.

Результат до виправлень: 46/50 браузерних перевірок. Після: 50/50. Критичних проблем (поломка відправки, JS-винятки, XSS, неможливість заповнити форму з клавіатури) не знайдено.

Рівні: **Критичний** — форма не працює або небезпечна; **Середній** — порушення WCAG AA, баг, який користувач помітить, або суттєва вада підтримуваності; **Низький** — дрібниці й покращення.

## Що перевірено і проблем не виявлено

- **JS**: жодного винятку чи `console.error` за весь прогін; подвійний submit (Enter ×2 + `requestSubmit()`) відкриває модалку один раз.
- **XSS**: усі тексти виводяться через `textContent`; `<script>alert(1)</script>` в імені — помилка валідації, у повідомленні — звичайний текст, `alert` не викликається.
- **Розмітка**: у кожного поля є `label[for]`, `name`, `aria-describedby` на свій `<p aria-live="polite">`; id унікальні; `lang="uk"`.
- **Клавіатура**: порядок Tab логічний; Enter надсилає; фокус переходить на перше невалідне поле; у модалці фокус на «Закрити», Tab/Shift+Tab не виходять, Esc закриває, після закриття фокус на «Надіслати»; решта сторінки `inert`.
- **Контраст тексту**: підписи 10.35:1, підказки й лічильник 4.76:1, помилки 4.83:1, зелені примітки 5.02:1, кнопка 5.48:1.
- **Адаптивність**: 320px — одна колонка, без горизонтального скролу, тексти помилок переносяться; від 768px ім'я та email у два стовпці; поля й кнопки ≥ 44px; шрифт полів 16px (без масштабування на iOS); модалка 288px на екрані 320px.
