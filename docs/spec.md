# Специфікація форми зворотного зв'язку EQUILOCK

## 1. Мета

EQUILOCK — escrow-платформа для P2P/OTC угод USDT/UAH. Форма дає користувачу змогу поставити питання про угоду чи роботу escrow і залишити контакти для відповіді.

Форма працює без бекенду: дані перевіряються на клієнті, а після успішної перевірки показується модальне вікно з поясненням, що надсилання імітоване.

## 2. Поля

Усі поля обов'язкові. Атрибут `novalidate` на формі вимикає стандартні підказки браузера. Правила перевірки — у `assets/js/validators.js`, поведінка (події, стани, модалка) — у `assets/js/validation.js`.

| Поле | id / name | Тип | Правило | Обмеження |
|---|---|---|---|---|
| Ім'я | `name` | `text` | ≥ 2 символи; кирилиця/латиниця, апостроф, дефіс, пробіл | `maxlength="50"` |
| Email | `email` | `email` | `^[^\s@]+@[^\s@]+\.[^\s@]{2,}$` | `maxlength="254"` |
| Телефон | `phone` | `tel` | `^\+380\d{9}$` (після нормалізації) | `maxlength="25"` |
| Повідомлення | `message` | `textarea` | ≥ 10 символів без пробілів на краях | `maxlength="1000"`, лічильник |
| Згода | `agreement` | `checkbox` | має бути позначено | — |
| Надіслати | `submit-btn` | `submit` | — | блокується на час «надсилання» |

## 3. Тексти помилок

| Поле | Умова | Текст |
|---|---|---|
| Ім'я | порожнє | Введіть ім'я. |
| Ім'я | 1 символ | Ім'я має містити щонайменше 2 символи. |
| Ім'я | > 50 символів | Ім'я не може бути довшим за 50 символів. |
| Ім'я | недозволені символи | Ім'я може містити лише літери (кирилиця або латиниця), апостроф, дефіс і пробіл. |
| Email | порожнє | Введіть email. |
| Email | не відповідає RegEx | Введіть коректний email, наприклад name@example.com. |
| Телефон | порожнє | Введіть номер телефону. |
| Телефон | є літери | Номер не може містити літер. Формат: +380XXXXXXXXX, наприклад +380501234567. |
| Телефон | інші символи (`+` не на початку, `/`, `.` тощо) | Дозволені лише цифри, «+» на початку, пробіли, дужки та дефіси. Формат: … |
| Телефон | замало цифр | Замало цифр. Формат: … |
| Телефон | забагато цифр | Забагато цифр. Формат: … |
| Телефон | інший початок (`+0…`, `+1…`) | Номер має починатися з +380, 380 або 0. Формат: … |
| Повідомлення | порожнє / лише пробіли | Введіть повідомлення. |
| Повідомлення | < 10 символів | Повідомлення має містити щонайменше 10 символів. |
| Згода | не позначено | Потрібна згода на обробку персональних даних. |

Пояснення (зеленим) для телефону:

- після `blur`/`submit`, якщо номер перетворено: «Номер перетворено у формат +380XXXXXXXXX: +380501234567.»
- під час введення в уже перевірене поле: «Після виходу з поля номер буде перетворено у формат +380XXXXXXXXX.»

## 4. Стани поля

| Стан | Коли | Вигляд | ARIA |
|---|---|---|---|
| normal | початковий, після `reset` | рамка `border-slate-500` (4.76:1), hover — `slate-700` | `aria-invalid` відсутній |
| focus | поле у фокусі | рамка без змін + суцільне кільце `ring-2 ring-emerald-600` (3.77:1) | — |
| error | валідація не пройдена | рамка `border-red-500` (3.76:1), червоний текст `text-red-600` під полем, кільце фокусу `red-500` | `aria-invalid="true"` |
| success | валідація пройдена | рамка `border-green-600` (3.30:1), за потреби зелене пояснення `text-green-700`, кільце фокусу `green-600` | `aria-invalid="false"` |

Кольори підібрано так, щоб межі полів і focus ring мали контраст ≥ 3:1 з білим фоном (WCAG 1.4.11). Через це success-рамка — `green-600`, а не `green-500` з початкового ТЗ (2.28:1); див. [audit.md](audit.md), А-1…А-4.

Для чекбокса рамка стану малюється на обгортці `[data-highlight-for="agreement"]`.

Кожне поле має `aria-describedby` на свій `<p id="…-error" aria-live="polite">`; у телефону — ще й на постійну підказку `phone-hint`.

## 5. Коли запускається валідація

| Подія | Дія |
|---|---|
| Завантаження сторінки | нічого не перевіряється |
| `blur` | поле позначається «торкнутим» і перевіряється; ім'я/email обрізаються, телефон нормалізується |
| `input` | перевіряється лише вже торкнуте поле; значення не переписується |
| `change` (чекбокс) | перевірка згоди |
| `submit` | `preventDefault`, перевірка всіх полів, фокус на першому невалідному |

## 6. Успішне надсилання

1. Кнопка блокується (`disabled`, `aria-busy`, текст «Надсилання…») — повторний submit ігнорується.
2. Через 600 мс (імітація запиту): `form.reset()`, очищення всіх станів і лічильника.
3. Відкривається модальне вікно: `fixed inset-0`, затемнений фон, картка по центру, текст «Це імітація надсилання: дані пройшли клієнтську валідацію, але нікуди не відправляються».
4. Фокус — на кнопці «Закрити», `Tab`/`Shift+Tab` не виходять за модалку, решта сторінки — `inert`, скрол сторінки заблоковано.
5. Закриття: кнопка «Закрити», `Esc`, клік по фону (клік по картці не закриває).
6. Після закриття кнопка «Надіслати» розблоковується й отримує фокус.

## 7. Поведінка на мобільних

- Mobile-first: одна колонка; від `md` (≥ 768px) ім'я та email стоять у дві колонки.
- Висота полів і кнопок ≥ 44px (`min-h-11`), уся область підпису чекбокса клікабельна.
- `text-base` (16px) у полях — iOS Safari не збільшує масштаб при фокусі.
- `inputmode="tel"` / `inputmode="email"` відкривають відповідну клавіатуру; `autocomplete` дозволяє автозаповнення.
- Кнопка «Надіслати» на мобільних на всю ширину, від `md` — за вмістом.
- Без горизонтального скролу на 320px: відступи `px-4`, `min-w-0` у колонках сітки, `break-words` для текстів помилок.
